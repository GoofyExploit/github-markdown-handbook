# What is Markdown?

Markdown is a **lightweight markup language** used to format plain text.

Unlike HTML, Markdown uses simple, readable symbols to create formatted documents.

For example:

```md
# Heading

**Bold**

*Italic*

- List Item
```

becomes

# Heading

**Bold**

*Italic*

- List Item

The goal of Markdown is to let you write documents that are:

- Easy to read
- Easy to write
- Easy to convert into HTML

---

# Why was Markdown Created?

Markdown was created in **2004** by **John Gruber**, with help from **Aaron Swartz**.

At that time, writing HTML documents required a lot of tags like:

```html
<h1>Hello</h1>

<p>This is a paragraph.</p>

<strong>Bold</strong>
```

Markdown simplified this to

```md
# Hello

This is a paragraph.

**Bold**
```

Much easier to write.

---

# Why Does GitHub Use Markdown?

GitHub hosts millions of software projects.

Every project needs documentation.

Instead of forcing developers to write HTML pages, GitHub automatically converts Markdown into beautiful HTML pages.

That means you can focus on writing instead of designing web pages.

---

# What is a README?

A README is the **homepage of your project**.

It explains:

- What the project is
- Why it exists
- What problem it solves
- How to install it
- How to use it
- What technologies it uses

Most visitors decide within **30 seconds** whether a repository is worth exploring.

Your README is what creates that first impression.

---

# Why is Documentation Important?

Many beginners think:

> "The code speaks for itself."

In reality, it doesn't.

Imagine opening a repository that contains only source code.

```
project/

src/

main.py

utils.py

config.py
```

Questions immediately come to mind:

- What does this project do?
- How do I run it?
- Which Python version is required?
- Which dependencies should I install?
- Is it still maintained?

A README answers all of these questions.

Documentation saves time for everyone—including your future self.

# Why Every GitHub Repository Needs a README

A good README makes your repository:

- Easier to understand
- Easier to use
- Easier to contribute to
- More professional
- More likely to receive stars

Even small personal projects benefit from clear documentation.

# Markdown vs HTML

Markdown is designed for writing documentation.

HTML is designed for building web pages.

| Markdown | HTML |
|----------|------|
| Easy to learn | More complex |
| Quick to write | More verbose |
| Readable as plain text | Filled with tags |
| Great for documentation | Great for websites |

GitHub also supports a limited amount of HTML inside Markdown.

You'll learn about this in a later chapter.

# Common Markdown Files

Some of the most common Markdown files you'll encounter are:

| File | Purpose |
|------|---------|
| README.md | Project documentation |
| CONTRIBUTING.md | Contribution guidelines |
| CHANGELOG.md | Version history |
| CODE_OF_CONDUCT.md | Community rules |
| SECURITY.md | Security policy |
| LICENSE.md | Project license |
| ISSUE_TEMPLATE.md | GitHub issue template |

You'll probably write several of these as your projects grow.

# Common Beginner Mistakes

Many new developers make the same mistakes:

❌ No README at all

❌ Huge walls of text

❌ No installation instructions

❌ No screenshots

❌ No project description

❌ Poor formatting

❌ Outdated documentation

Remember:

> **Good code gets noticed. Good documentation gets used.**
